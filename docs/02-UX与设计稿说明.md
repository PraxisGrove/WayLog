# 体验与设计系统 · UX & Design System

> 本文定义当前核心工具界面的布局、主题与交互边界。
> 更新基线：2026-10-09。Token 数值与可用组件以 `shared/theme/`、`shared/ui/` 和页面实现为准。

## 设计目标

WayLog 的界面首先帮助用户看清旅行信息、完成编辑并理解状态。
移动端优先，桌面保留可用的内容宽度与交互方式；视觉强调服务于信息层级和关键操作。

当前默认模式是白底、浅灰背景、黑白主色的简洁骨架。
简洁模式保留经典调色板、基础卡片与旅行票券元素。两种模式均通过同一主题解析入口提供 token 和 recipe。
默认模式使用稳定的 `default` identity；当前线框外观与后续视觉完善沿用同一主题标识，不额外创建“线框皮肤”。
后续正式默认皮肤、其它主题与导出模板各自定义视觉语言，不把单个主题的偏好当作全局限制。

## 当前主题结构

```text
AppThemeProvider
  -> 主题选择 / 明暗模式 / 用户偏好
  -> resolveTheme()
  -> ResolvedTheme
     -> tokens
     -> component recipes
     -> layout presets
     -> skin slot adapters
  -> 页面与共享组件
```

| 源码入口 | 职责 |
| :-- | :-- |
| `shared/theme/theme-registry.ts` | 当前主题列表与默认主题 |
| `shared/theme/resolve-theme.ts` | 组合主题定义、token 与组件 recipe |
| `shared/theme/base-design-tokens.ts` | 间距、圆角、字阶、布局和动效基线 |
| `shared/theme/default-design-tokens.ts` | 默认模式的黑白与表面层级 |
| `shared/theme/design-tokens.ts` | 调色板、语义状态、阴影与地图视觉 |
| `shared/theme/recipes/` | 按组件类型解析视觉配方 |
| `shared/theme/skin-slot-registry.ts` | 完整 UI 模块的 Slot 与 Adapter 白名单 |
| `shared/theme/use-app-theme.ts` | 页面读取解析后的主题 |

业务操作、表单校验、确认策略和数据写入由 domain 与 feature 控制。
主题可以提供视觉与布局 preset，但不拥有业务流程或写权限。

Slot 只覆盖注册的完整模块，例如行程卡、底部导航、资料卡、账本/清单预览和 Agent 卡片。
按钮、基础卡片、输入框、弹层和徽章跟随主主题 recipe，不提供独立混搭入口。
Adapter 必须属于对应 Slot，覆盖项还须满足 `ready`、允许用户覆盖和当前主题白名单三个条件。
完整账本/清单 Sheet 仍标记为 `todo`；当前 Provider 锁定布局 preset 与 Slot 自定义，加载时忽略旧覆盖偏好。注册了 Adapter 不代表已开放用户设置。

## Token 使用

优先引用语义 token，例如 `colors.text`、`surface`、`primary`、`danger`、`focusRing`。
同一种状态在不同页面使用同一含义；页面私有值只用于确有必要的布局细节。

| 类别 | 当前基线 | 使用原则 |
| :-- | :-- | :-- |
| 间距 | 4、8、16、20、28、36 | 优先使用 `spacing` 维持页面节奏 |
| 圆角 | 基础 8、12、16、20、24；默认 6、8、10、12、16 | 容器与控件依据当前主题 recipe 选择 |
| 字阶 | 标题 32/40，正文 15/22，说明 13/18 | 数值为字号/行高，以实际组件为准 |
| 布局 | 内容 padding 20，最大宽度 620 | 适配窄屏，宽屏保持阅读宽度 |
| 动效 | 120、200、320 ms 与共享 spring | 按操作反馈需求选择 |
| 阴影 | card、floating、sheet；默认模式为零阴影 | 表达层级，避免每个模块自建重阴影 |
| 地图 | marker、路线、区域 token | 地图图形与普通卡片分别管理 |

默认模式的语义状态常使用黑白与文字区分，不能仅凭颜色表达成功、危险或选中。
新增视觉值时同时检查明暗模式、禁用态、按下态和可读性。

## 页面壳层

- 顶部导航、标题、搜索区在 scope 或状态切换时保持稳定。
- 页面编排定义区域顺序，跨页面基础容器放在 `shared/ui/`。
- 长内容滚动，主操作和底部安全区保留明确空间。
- 横向选择器用于真实分类、模式或高频筛选，不为装饰增加分组。
- 空态提供与当前任务相关的下一步；加载态与错误态不能覆盖已有本地内容。

普通卡片优先通过背景、留白和轻阴影形成边界。
输入区域使用容器背景与聚焦状态；选中、危险、错误、焦点等语义边框通过 token 表达。
重点组件可使用票券、标签、内高光或适度立体层级，但整屏保持清爽的旅行工具气质。

## 弹层与编辑

| 形态 | 适用任务 | 交互要求 |
| :-- | :-- | :-- |
| 确认 Dialog | 简短确认、危险操作 | 清楚描述影响范围与确认动作 |
| 操作菜单 | 有限动作选择 | 选项命名具体，可取消 |
| 表单 Sheet | 局部编辑、日期或地点选择 | 键盘与滚动区域可用，校验贴近字段 |
| 全屏 Modal / 编辑容器 | 多步骤或较长内容 | 明确保存、关闭及未完成状态 |
| 阻塞/加载状态 | 正在执行不可重复动作 | 显示真实状态，防止重复提交 |

弹层外壳负责关闭、层级、安全区和键盘行为；业务内容留在对应 domain。
复杂表单不能依赖一个普通确认框承载完整流程。

## 行程与地图

行程详情按真实日期、每日安排和相关记录组织信息。
长地点名称、缺失坐标、无天气数据和路线失败都有可理解的展示方式。
调用导航优先使用本机地图 App，用户仍可以回到行程继续操作。

地图详情使用沉浸画布与底部抽屉。抽屉通过表面、handle 和层级区分，不套用普通卡片外框。
日期 Tab 保持固定高度；切换选中项不能撑高布局。
地点 marker、名称胶囊、路线与区域视觉优先归入地图 token，避免随普通卡片样式一起误改。

## Agent 会话

- 输入区固定在底部，消息只在其上方滚动；键盘和安全区不能遮住发送与确认动作。
- 历史加载后直接定位最新消息，不播放跨越整段历史的长滚动动画。
- 进度来自真实模型、工具和校验事件，不能用计时器伪造完成感。
- 草案、澄清、候选、提案、失败与应用回执分别展示对应动作。
- 确认前展示变化与风险；强确认不能弱化为普通发送或继续按钮。
- 应用中阻止重复点击；重复确认展示已有结果，冲突提示重新生成。
- 调试区只展示公开摘要、usage、耗时和错误码，不展示隐藏推理或完整工具 payload。

## 无障碍与移动端验收

以下是变更验收要求，不代表全应用已完成无障碍认证。

- 交互元素有可理解的标签、角色和状态；图标按钮不能只靠图形表达意图。
- 用文字、图标或形状补充颜色语义，检查明暗模式中的对比度。
- 检查小屏、长文本与放大字体，重要动作保持可点击、可滚动。
- 检查键盘、刘海、手势区域、Android 导航栏与返回行为。
- 动效可被取消和打断；尊重系统减少动态效果偏好，保留清晰的静态反馈。
- 触觉或声音只作为补充反馈，关闭或不可用时仍能完成任务。
- 网络或地图服务不可用时保持已有本地行程可读、可编辑。

## 设计变更流程

1. 明确用户任务和信息层级，再确定页面结构。
2. 检查现有 token、recipe、共享组件和 slot，优先复用已定义能力。
3. 实现完整的默认、加载、错误、空态、选中和禁用状态。
4. 运行 lint 与类型检查，检查 Android/iOS 小屏和 Web 布局。
5. 记录仍未验证的平台或真机限制；结构或交互边界变化同步更新当前架构、数据合同与验收说明。
