# 测试与发布验收 · Quality & Release

> 本文定义验证层次、核心回归与自有环境的发布检查。
> 更新基线：2026-10-09。可执行命令以 `package.json` 和 `scripts/` 为准；未运行的检查如实记为未验证。

## 验证层次

| 层次 | 命令 | 通过标准 |
| :-- | :-- | :-- |
| 业务与契约回归 | `pnpm test` | 当前测试目标通过，失败可定位 |
| 类型检查 | `pnpm typecheck` | TypeScript 检查通过 |
| 静态质量 | `pnpm lint` / `pnpm format:check` | Biome 检查通过 |
| Web 产物 | `pnpm build:web` | Expo 静态导出成功 |
| Agent UI 清单 | `pnpm agent:ui-regression` | 打印当前可执行回归要求 |
| Agent UI 自动回归 | `pnpm test:agent-ui` | 测试账号完成预览、确认与真实本地变化 |
| Agent 自然语言路由 | `pnpm agent:route-eval` | 自有认证 Edge 与模型对固定语料返回正确路由 |
| Agent 草案事实核验 | `pnpm agent:trip-draft-eval` | 语义、澄清、POI grounding 与失败边界符合合同 |
| Pi RN 兼容 | `pnpm agent:pi-compat` | Production bundle、Hermes 与 fixture 通过 |
| Android 本地 APK | `pnpm apk build-only` | 自有正式签名产物可安装并完成真机验收 |

`pnpm test` 先清理 `.tmp-test-dist/`，按 `tsconfig.test.json` 编译，再由 `scripts/run-tests.js` 运行 Node `node:test`。
编译范围和排除项以测试配置为准，不把脚本成功等同于所有页面和平台已验证。
测试数量随提交变化，公开文档不固定历史测试总数。

## 按变更选择检查

| 变更 | 必需验证 |
| :-- | :-- |
| `features/` 纯业务规则 | 对应回归测试；正常、异常与边界输入 |
| Trip 类型、存储或同步 | `pnpm test` + `pnpm typecheck`，检查旧数据兼容 |
| 页面、组件与样式 | `pnpm lint` + 类型检查，Android/iOS 小屏布局 |
| Agent operation、授权或 ApplyFlow | 无授权、幂等、CAS、整张原子性与补偿 |
| 路由元数据、RouteSelector 或模型配置 | 真实模型语料评估，不用 mock 代替自然语言验收 |
| 草案 schema、POI 或 continuation | 对应单测与真实草案评估 |
| Pi 版本或 RN 补丁 | 兼容 fixture 与 Android/iOS Release/native probe |
| 发布配置、认证或原生模块 | 对应签名构建、真机与服务端联调 |

修复缺陷先补能复现问题的回归测试，再改实现。
只描述实际验证证据；远端不可用、无凭据或缺少设备时记录具体阻塞与仍需完成的项目。

## 核心数据回归

- 离线创建、编辑、删除 Trip 后本地立即可见。
- dirty 与删除标记在网络失败后保留，重试后正确清除。
- 旧 AsyncStorage 与云端 JSONB 正常规范化，稳定 ID 与 1-based 天序不变。
- 云端软删除、远端更新和本地 dirty 冲突符合现有规则。
- 同步途中再次修改，不被旧同步结果覆盖或清除 dirty。
- 并发创建、更新、回滚与元数据写入不丢失其它实体。
- 登录、登出、会话刷新与账号切换不破坏数据与权限边界。

## Agent 安全回归

| 场景 | 通过标准 |
| :-- | :-- |
| 只生成提案或草案 | Trip 无变化 |
| 未确认或无有效授权 | 写入被拒绝，未授权写入率为 0 |
| 正常确认 | 正确应用，返回回执并标记 dirty |
| 无效参数或目标不存在 | 提交前拒绝 |
| 未核验、跨地区或身份不匹配 POI | 提交前拒绝 |
| 重复确认 | 不重复写入，返回既有结果 |
| 版本变化 | 返回冲突，要求重新生成 |
| 多 operation 中任一失败 | 整张提案不产生部分成功 |
| 回执前写入失败 | 恢复本操作拥有的本地状态 |
| 云同步失败 | 本地成功保留，dirty 留待重试 |
| 取消、重试与应用恢复 | Attempt 状态真实，无旧输出隐式复用 |
| 账号切换 | 无其它账号历史或 PendingState 泄漏 |
| 外部 prompt injection | 无权限提升或协议绕过 |
| 外部来源持久化 | 仅保存有界引用，无正文、token 或 signed URL |

## Agent UI 回归

先运行清单，按当前脚本准备专用测试行程与测试账号：

```bash
pnpm agent:ui-regression
pnpm agent:ui-regression:run --trip-id <synthetic-trip-id> --trip-title <synthetic-trip-title> --day6-date <day6-label> --day7-date <day7-label>
# test:agent-ui 是同一入口，也必须传入上述四个参数
```

自动脚本会修改测试行程。使用合成数据和自有测试账号，通过参数选择行程与预览地址。
登录凭据在本地环境配置，不把账号、密码、access token 放在命令示例或 Issue 中。
行程 ID、标题及第 6/7 天的日期标签必须显式提供；缺少参数会在启动浏览器前失败。运行前按脚本输出检查前置条件。

| 用例 | 观察点 |
| :-- | :-- |
| 添加地点 | 候选核验、提案预览、确认后目标天新增安排 |
| 修改备注或时间 | 预览差异正确，确认后详情显示新值 |
| 移动安排 | 两天的结果正确，稳定 item ID 保留 |
| 删除安排 | 影响范围与强确认明确，取消无变化 |
| 恢复测试状态 | 合成行程回到可重复测试的状态 |
| 刷新或重启 | 公开历史、pending 与回执正确恢复 |

Playwright 资源属于当前测试任务，使用独立会话并在完成、失败或取消后关闭。
如果自动脚本失败而手动通过，分别核对选择器和业务链路，不能直接忽略失败。

## 真实模型评估

`agent:route-eval` 与 `agent:trip-draft-eval` 使用自有认证 Edge、模型和 POI 服务，可能产生服务请求与额度消耗。
环境变量及参数从脚本读取，所有凭据留在本地环境或 CI secret。

评估需记录提交、语料版本、App/协议版本、模型配置与通过/失败结果。
服务版本门禁、quota、网络或供应商失败应分类记录；固定语料未执行不能报告为通过。
受控单测与真实模型评估分别提供确定性规则和自然语言/外部事实证据。

## Android 构建与签名

本地发布由 `scripts/release-android.js` 管理，使用 JDK、Android SDK、Expo prebuild 与 Gradle。
先配置自己的 `.env.local`、SDK 路径和受控 Release keystore，再执行：

```bash
pnpm apk build-only
```

| 配置 | 用途 |
| :-- | :-- |
| `ANDROID_HOME` / `ANDROID_SDK_ROOT` | Android SDK |
| `JAVA_HOME` | 脚本所需 JDK |
| `KEYSTORE_PATH` | 自有签名文件路径 |
| `KEYSTORE_PASSWORD` / `KEY_ALIAS` / `KEY_PASSWORD` | 自有签名凭据 |
| `PGYER_API_KEY` | 可选蒲公英分发凭据 |
| `GITHUB_TOKEN` / `GH_TOKEN` 或已登录 `gh` | 可选自有 GitHub Releases 发布权限 |

脚本缺少正式签名时失败，不自动生成临时 Release 签名。
已发布的应用持续使用原签名；示例 keystore、密码和平台指纹不得进入仓库。
签名检查工具包括 `scripts/get-android-signature.sh`，最终以实际 APK 为准。

`pnpm apk pgyer`、`pnpm apk github` 和 `pnpm release` 含外部发布动作。
运行前确认自有目标仓库、分发应用和版本策略，测试通过不自动授权发布。
脚本成功上传后保留注入的发布版本；未发布的构建失败按脚本恢复配置。
产物位置与版本行为检查当前脚本输出，不依赖旧截图或固定版本号。

## 原生与发布检查

- 在 Android/iOS 小屏检查键盘、安全区、返回、长列表与底部主操作。
- 在真实签名 App 中检查认证、地图、导航和相关原生 SDK。
- 验证添加 → 预览 → 确认 → 删除 → 强确认完整闭环。
- 验证重启、断网、会话过期、同步重试与重复确认。
- 核对公开客户端配置、服务端 secret、RLS、版本与服务开关。
- 核对 APK/应用版本、签名、安装升级和发布说明。
- 上传产物前检查源映射、日志与截图是否包含真实个人数据或凭据。

iOS Release 需要自有签名、设备和对应 SDK 配置；模拟器辅助构建不等同于真机验收。
当前云构建支持以实际配置为准，不能根据历史文档假设 EAS 工作流存在。
