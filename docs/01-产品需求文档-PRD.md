# 产品需求 · Product Requirements

> 一路记 WayLog：个人旅行控制台与旅行手账。本文定义当前范围、能力状态与验收原则。
> 更新基线：2026-10-09。实现细节以当前源码、测试与 [Agent Runtime 合同](agents/agent-runtime.md) 为准。

## 产品定位

WayLog 把旅行日期、每日安排、地点、交通、住宿、预算、费用、备忘和行前清单放在同一个工作空间。
用户可以手动维护行程，也可以让 Agent 生成草案或编辑提案，查看影响后再决定是否应用。

当前阶段是旅行核心能力稳定化与 Agent MVP 打磨。产品优先保障个人数据可靠、手机端易用和编辑过程可控。
开源版本提供应用源码、业务规则、测试和部署材料；线上认证、地图、模型等服务需要部署者自行配置。

## 用户与场景

| 场景 | 用户任务 | 产品价值 |
| :-- | :-- | :-- |
| 出发前 | 整理目的地、日期、候选地点和每日安排 | 将散落的信息收拢为可执行行程 |
| 旅行中 | 查看今天的安排、地图、天气和重要备忘 | 在小屏上快速找到下一步 |
| 记账时 | 记录费用、关联日期或地点、查看分类汇总 | 保持旅行预算与实际花费可追踪 |
| 计划调整 | 添加地点、改时间或备注、移动或删除安排 | 支持手动编辑和可预览的 Agent 提案 |
| 旅行后 | 回看旅行内容和花费 | 保留有结构的个人旅行记录 |

## Agent 产品合同

### 三个顶层 Skill

| Skill | 输出 | 用户操作 |
| :-- | :-- | :-- |
| `trip.draft` | 经过地点核验的新行程草案或澄清请求 | 补充目的地/天数，预览后点击创建 |
| `itinerary.edit` | 已有 Trip 的结构化编辑提案或目标选择 | 选择目标 Trip，检查差异与风险后确认 |
| `waylog.qa` | 应用使用说明和只读旅行回答 | 阅读回答，必要时查看来源 |

常用编辑操作包括 `add_place_to_day`、`update_day_item`、`move_day_item`、`remove_day_item`。
`ensure_trip_day_count` 用于补齐天数；它仍必须遵循整张提案校验与风险策略。

### 交互规则

1. 自由文本先由云端 RouteSelector 分类，再运行选中的 Skill。
2. 目的地、天数或目标行程不明确时，用结构化澄清或选择卡继续任务。
3. 草案与提案展示可理解的影响范围；模型生成本身不修改 Trip。
4. 创建新行程必须由用户点击创建；快捷代办不能创建 Trip。
5. 快捷代办由用户显式开启，只适用于通过客户端检查的单个低风险编辑。
6. 删除、多操作、中高风险或影响不确定的编辑必须强确认。
7. 错误、取消和版本冲突保留明确反馈，不以猜测或隐式降级完成写入。

### 来源与事实

真实地点必须由受控 POI 工具候选核验身份与地区，不能仅凭模型生成的名称或坐标写入。
天气与路线回答要说明来源；路线估算不作为预订或实际导航指令。
公开网页检索只在用户明确请求时启用，持久化仅保存标题、平台、安全链接和抓取时间等来源引用。

## 开发优先级

| 优先级 | 目标 | 完成标准 |
| :-- | :-- | :-- |
| P0 · 稳定性 | 旅行、认证、同步、移动端与发布链路 | 核心流程无阻塞回归；本地修改与失败重试可验证 |
| P1 · Agent MVP | 草案与真实地点编辑闭环 | 预览、确认、幂等、冲突和失败补偿符合合同 |
| P2 · Agent 体验 | 历史上下文、usage 展示与页面职责收敛 | 不扩大写权限，改进可理解性与可维护性 |
| P3 · 计划能力 | 评估独立 `ScheduleEvent` 领域 | 另行定义数据与范围，不扩张 Trip 为通用日历 |
| P4 · 内容与手账 | 验证用户主动导出的旅行结果物 | 基于真实 Trip，由用户保存或通过系统分享 |

P3、P4 是后续方向，不是当前功能承诺。需求冲突时先保护 P0 与 Agent 授权边界。

## 当前不纳入范围

- 社区、关注流、评论、推荐系统和公开内容平台。
- 多人协作、商业订单、自动预订或支付。
- 通用日历、重复日程与完整 `ScheduleEvent` 系统。
- 后台自主 Agent、未授权自动修改、持续语音监听。
- 长期记忆、向量库、跨设备 Agent 对话同步。
- 外部内容平台的后台批量抓取、原文搬运或全文知识库。
- 复杂地图离线包、通用办公导出和复杂商业皮肤系统。

这些边界只描述当前阶段；新方向需要单独的需求、决策记录与验收方案。

## 质量指标

| 维度 | 验收口径 |
| :-- | :-- |
| 数据可靠性 | 本地先写、失败保留 dirty、软删除可补同步 |
| Agent 授权 | 未确认或未授权写入率为 0 |
| Agent 幂等 | 重复确认不重复创建或修改 |
| Agent 一致性 | 目标不存在、参数无效、版本冲突均在写入前阻止 |
| 移动端体验 | 小屏、键盘、安全区、弱网和登录变化下核心操作可用 |
| 发布可追踪性 | 版本、签名、构建环境与测试结果有对应记录 |
