## 可信度与冲突处理

1. 当前产品边界、数据写入与安全合同定义应保持的行为。
2. 源码、测试、migrations 和配置说明当前实现。
3. 架构或领域变更同步更新对应的当前合同，避免依赖过期笔记。
4. 平台价格、政策、额度或接口能力使用前查对应官方资料，不复用旧调研结论。

发现合同与实现冲突时先识别缺陷或过期文档，修复并更新对应回归。
不能以实现偶然绕过合同为理由降低授权、隐私或本地优先保障。
文档中的“已实现”不等同于远端已部署、所有模型评估通过或所有平台已完成真机验收。

## 公开文档边界

公开材料只保留可复现的开发说明、占位配置和合成示例。
本地个人笔记、生产账号、真实用户数据、签名材料、凭据、私有运维记录与第三方正文不进入仓库。
历史决策记录、工单执行流程、阶段蓝图、术语调研、演示草稿和独立项目规划保留在本地忽略目录。

安全问题遵循 [安全政策](../SECURITY.md)，不在公开 Issue 粘贴密钥或真实会话。
提交截图、日志和模型评估报告前移除访问 token、signed URL、个人联系方式与旅行隐私。

## 文档维护

- `README.md` 负责产品入口；`CONTRIBUTING.md` 负责协作流程。
- `AGENTS.md` 负责稳定规则；阶段性状态不回流到执行手册。
- `docs/01–05` 和 Agent Runtime 维护当前开发合同；影响实现的决策同步更新对应文档。
- 环境和命令集中到开发指南，以当前脚本为事实来源。
- 新能力标明状态、边界与验收条件，未实现内容保持清晰的后续方向。
- 相对链接使用仓库内实际路径，重命名或移除文档时同步修复入口。
- 每份文档只保留会影响使用、开发或评审的内容，避免流水账与重复规则。
