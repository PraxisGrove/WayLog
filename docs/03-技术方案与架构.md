# 技术架构 · Architecture

> 本文说明当前代码分层、数据流与 Agent 权责，供开发、评审和功能扩展使用。
> 更新基线：2026-10-09。Agent 的完整当前合同见 [agents/agent-runtime.md](agents/agent-runtime.md)。

## 技术基线

应用使用 React Native 0.81、Expo SDK 54、TypeScript 5.9、Expo Router 与 React Navigation。
Trip 使用 AsyncStorage 本地优先存储；Agent 记录通过 Expo SQLite 的本地数据库层持久化。
Supabase 提供认证、Postgres、RLS 与 Edge Functions。地图和天气通过各自 feature 接入外部服务。
包管理与脚本入口以 `package.json`、`pnpm-workspace.yaml` 和 lockfile 为准。

## 分层与依赖

```text
app -> shell -> domains -> features
             domains -> shared
             shell   -> shared

features 不依赖 app / shell / domains
shared 不依赖 domains
不同 domains 之间不互相 import
```

| 目录 | 职责 | 边界 |
| :-- | :-- | :-- |
| `app/` | 文件路由、参数、layout、redirect | 保持薄入口，不承载业务规则 |
| `shell/` | Provider、导航外壳与全局生命周期 | 不承载具体业务页面 |
| `domains/` | 页面编排、交互状态、私有组件 | 通过 feature 读写数据 |
| `features/` | 类型、领域命令、存储、同步、协议与服务 | 不放 React 组件 |
| `shared/` | 跨区 UI、主题、Hook 与工具 | 能力型 UI 使用明确子目录 |
| `modules/` | Expo 本地原生模块 | 不新建产品业务目录 |
| `supabase/` | migrations、Edge Functions 与服务端配置 | 使用自有部署，私密凭据留在环境中 |
| `admin-web/` | 管理端 workspace 应用 | 管理职责与用户 App 分开 |
| `os-web/` | 静态产品展示站 | 与 App Web 导出分别构建和部署 |
| `tests/` | 业务与契约回归 | 用可观测行为验证规则 |
| `scripts/` | 构建、评估、诊断与维护工具 | 明确区分本地操作和外部写入 |

## Trip 写入链路

```text
页面或已授权 Agent
  -> features/trips/commands.ts（领域变换与校验）
  -> features/trips/storage.ts
  -> AsyncStorage 本地写入
  -> dirty / 删除标记
  -> 后台 cloud-sync
  -> Supabase user_trips
```

页面、Agent 和 Edge 都不能绕过本地链路直接修改 `public.user_trips`。
领域命令返回新 Trip，不原地修改输入；批量操作先完整验证，再提交。
Trip 集合读改写由本地写入协调器串行化，完整同步元数据对象有独立写锁。
同步失败保留本地成功结果与 dirty，下次重试；删除采用软删除。

数据格式、POI 引用和兼容规则见 [数据合同](04-数据模型与API契约.md)。

## Agent：生成与应用分离

```text
用户自由文本
  -> Proposal Generation（只读）
     -> RouteSelector Pi run
     -> selected Skill Pi run
     -> 回答 / 澄清 / 草案 / 编辑提案 / 失败
  -> 用户结构化确认或有效快捷代办授权
  -> Confirmed Apply（客户端可写）
     -> Validator -> ApprovalGate -> ApplyFlow
     -> 本地 Trip -> dirty -> 回执 -> 后台同步
```

Pi 管理 Agent loop、流式事件、工具调用、取消和终止。
WayLog 管理范围、上下文、运行时 schema、地点事实、风险、授权、幂等、冲突与写入。
模型、Pi、Skill、工具、Edge 与预览卡均不拥有 Trip 写权限。

### 两阶段上下文

RouteSelector 只接收原始消息、最小页面信息、轻量 Skill 路由元数据和内建 handler。
它只暴露 `waylog_route` terminating tool，不读取完整 Trip 或 Skill 正文，也不产生 operation。
通过运行时校验后，第二个独立 Pi run 才加载选中 Skill 的说明、schema、裁剪上下文与只读工具 allowlist。

当前顶层 Skill 为 `trip.draft`、`itinerary.edit`、`waylog.qa`。
编辑目标由客户端读取本地 Trip 摘要解析；多候选先让用户结构化选择。
澄清续跑与确认属于本地结构化事件，不重新按自由文本路由。
模型、网络或协议失败形成公开失败结果，不通过关键词或字符串截取猜测写入。

### 移动端运行环境

`features/agent/pi-runtime.ts` 是创建 Pi Agent 的唯一入口。
Pi 依赖精确版本与 RN 补丁由 workspace 配置管理，模型流由认证后的代理适配器注入。
升级需验证 production bundle、Hermes 与 Android/iOS 原生兼容，不能只依赖 Node 测试通过。

### Proxy 与事件

`agent-llm-proxy` 从 JWT 推导身份，校验版本、phase、profile、服务开关和额度。
服务端持有模型凭据、正式提示词与 provider 配置；客户端 `userId` 或 `systemPrompt` 不能作为权限来源。
Edge 不直接写 Trip，也不向客户端返回密钥。

SSE 和工具参数在客户端再次校验；Pi 原始事件投影为版本化的公开 UI 事件。
进度来自真实 orchestration。隐藏推理、完整 provider payload、系统提示词与完整工具结果不进入 UI 或持久化。

## Confirmed Apply

| 路径 | 关键检查 | 成功结果 |
| :-- | :-- | :-- |
| 新建 Trip | 持久化草案、revision、连续天序、POI 身份、明确创建事件 | 稳定创建 ID 与创建回执，重复请求返回既有 Trip |
| 编辑 Trip | schema、目标、operation ledger、`expectedUpdatedAt`、整张 dry run、授权 | 原子应用整张提案并记录编辑回执 |

创建快捷代办不开放。编辑快捷代办仅可应用用户显式启用后的单个低风险 operation。
删除、多操作、中高风险、跨多处影响或未知风险需要强确认。
回执前失败按操作拥有的本地状态补偿；回执后的云同步失败保留本地结果与 dirty。

## 本地数据库与 Agent 状态

`features/local-db/` 统一数据库访问、事务与按 namespace 分隔的 key-value store adapter。
原生端复用单例 `waylog.db`；Web 的 key-value adapter 使用带 namespace 前缀的 AsyncStorage，不直接调用 SQLite。
数据库迁移集中在 `local-db-migrations.ts`，按全局递增 ID 执行并记录已应用版本；打开原生数据库时在事务内完成迁移。
当前迁移包含基础 key-value 表、Agent 应用 ledger 与审计引用字段。新增本地表沿用这一入口，不能在页面或 feature store 中另建迁移流程。

Conversation、Turn、Attempt 通过 `agent-local-storage.ts` 复用 `agent` namespace，并由会话存储键与读取校验按账号隔离。
旧 Agent AsyncStorage 数据读取时惰性迁移；Trip 仍使用自己的 AsyncStorage 格式与同步链路。
测试通过数据库或业务 store adapter 注入替身，不让业务代码直接依赖原生数据库对象。
同一任务重试保留 `turnId`、生成新 `attemptId`，全 App 同时只允许一个 active Attempt。
取消 abort 当前 Pi run；恢复时无内存执行的 running Turn 标记 interrupted。

消息只保存公开内容与引用；可执行草案、提案和 continuation 使用独立 PendingState。
消息文本不能被反解析成写入参数。当前本地历史不等于跨设备会话或长期模型记忆。

## 路线按需查询

详情页根据日期选择与时间轴可见区域确定当前 `selectedDay`，只把该日的路线段交给 `use-trip-route-segments.ts`。
总览没有选中日期时不发起每日路线查询；为全部日期构建路线段摘要是本地计算，不触发全行程预取。
`createTripRouteSegmentFetchPlan()` 根据路线段、地点快照与所选方式决定保留或查询；`getRouteSegmentWithCache()` 先复用有效缓存。
一次查询只取当前选定方式或距离规则选择的自动方式，其它交通方式由用户点选后按需请求。
缺少坐标与服务失败分别保留不可用状态或带来源标识的估算结果，界面不能把直线预览或估算时间当作真实道路路线。

## 外部数据与诊断

只读工具目前覆盖 POI、天气、路线估算和用户明确触发的公开网页检索。
工具返回、Trip 备忘和网页内容均是不可信数据，不能改变系统规则、allowlist 或授权。
外部资料持久化遵循来源引用边界，不保存正文、signed URL 或访问 token。

客户端诊断使用 Sentry React Native 与轻量本地 ring buffer。
遥测仅保留白名单摘要、usage、耗时、公开错误与操作数量；不收集完整用户消息、Trip JSON、JWT、密钥或隐藏推理。
公开 Issue 与日志使用脱敏样例。

## 模块与命名

页面私有代码与 screen 同目录；同 domain 复用放在该 domain，跨 domain 复用上移到 `shared/` 或 `features/`。
文件使用 kebab-case，组件使用 PascalCase，Hook 使用 `use-xxx.ts` 与 `useXxx`。
页面使用 `*-screen.tsx` 与 `XxxScreen`；自定义组件依据职责命名为 Card、Panel、Sheet、Dialog、Content 或 Section。
注释和复杂逻辑说明默认使用中文，协议字段与第三方术语保留原名。

## 扩展与验证

先实现纯领域能力和运行时合同，再接 UI、模型与存储。
变更领域规则或同步时增加回归测试；改页面检查小屏、键盘与安全区。
涉及 Agent 时覆盖未授权、重复确认、版本冲突、无效目标、工具失败和中途失败。
架构或安全边界变化同步更新当前架构、数据合同与 Agent Runtime，保持文档与源码、回归一致。
